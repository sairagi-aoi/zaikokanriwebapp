**在庫・発注管理Webアプリ｜v0.1**
 
一言で表すと、
 
**在庫そのものを管理するのではなく、在庫状況から「次に何をすべきか」を分かりやすく提示する業務支援Webアプリ**
 
です。
 
普通の在庫表のように「現在庫：3」と表示して終わるのではなく、
 
**現在庫 → 状態判定 → 必要な対応 → 次の行動**
 
までをつなぐことを狙っています。
 
JavaScriptウェブアプリ構想.md
 
**解決したい問題**
 
現在特に意識しているのは、
 
**在庫管理における意思決定の不透明さ**と、**発注が必要になった後の次の行動の分かりにくさ**です。
 
従来のExcelでは、人間が表を見て、
 
「これは発注が必要か」
「もう発注したか」
「いつ届くのか」
「予定日を過ぎていないか」
「次に何をすればいいか」
 
を自分で判断する必要があります。
 
このアプリでは、その確認・記憶・判断の一部をシステム側へ移します。
 
したがって、減らしたい負荷は大きく、
 
**確認負荷 → 判断負荷 → 行動決定の負荷**
 
です。
 
**プロダクトの中心思想**
 
かなり重要なのが、
 
**ExcelをWebアプリに置き換えることが目的ではない**
 
という点です。
 
Excelは引き続き詳細な情報を持つ**管理の正本・マスタ**として残します。
 
Webアプリはそのデータを利用しながら、
 
**今、業務上必要な情報だけを抽出して見せる**
 
役割を担当します。
 
JavaScriptウェブアプリ構想.md
 
イメージとしては、
 
Excel
 
完全な管理情報
 
        ↓
 
在庫・発注状態
 
        ↓
 
JavaScriptによる判定
 
        ↓
 
Web UI
 
「今どうなっている？」
 
「次に何をする？」
 
です。
 
**「在庫管理アプリ」より「業務ナビゲーション」に近い**
 
このアプリの特徴はここです。
 
たとえば、
 
コピー用紙
 
現在庫：3
 
発注点：10
 
→ 要発注
 
→ 発注してください
 
さらに発注後なら、
 
発注済み
 
入荷予定：9月15日
 
→ 入荷待ち
 
予定日を過ぎれば、
 
入荷予定日を超過
 
→ 要確認
 
→ 納品状況を確認してください
 
のように変化する。
 
つまり単なる在庫情報ではなく、**状態からNext Actionを生成する**ことが核です。

**現時点で考えているデータ**
 
設計メモでは、少なくとも、
- 商品名
- 現在庫
- 発注状況
- 次に取る行動
 
を扱う構想になっています。
 
元の構想ではさらに、
 
**① マスタデータ**
商品名、商品コード、発注点など
 
**② 状態データ**
現在庫、発注状態、入荷予定日など
 
**③ アクションデータ**
要発注、緊急発注、入荷待ち、要確認など
 
という3層で考えています。
 
JavaScriptウェブアプリ構想.md
 
特に「次に取る行動」は人間が毎回入力するというより、最終的には**現在の状態からJavaScriptが導き出すもの**にする方向です。
 
**現在考えている判定ルール**
 
設計メモでは、現時点の仮説として、
 
在庫 &lt;= 発注点
 
→ 要発注
 
在庫 0〜5
 
→ 緊急発注
 
在庫 &gt; 発注点
 
→ 在庫良好
 
発注済みでも、
 
入荷予定日を過ぎて未入荷
 
→ 要確認
 
などを考えています。
 
ただしこれはまだ**正式仕様ではありません**。
 
たとえば、
 
「全商品一律で5以下を緊急発注にしていいのか？」
 
「発注点・最低在庫・安全在庫はどう使い分けるのか？」
 
などは、これからリサーチして設計書で確定させる段階です。
 
**UI / UXの方向性**
 
ここもこのプロダクトの重要な特徴です。
 
目標は、
 
**行動に寄与する最小限の情報だけを表示する**
 
こと。
 
たとえば、
 
要発注
 
コピー用紙
 
現在庫：3
 
推奨：発注してください
 
のようにする。
 
状態についても、
 
**要発注 → 「要発注」という文字ラベル + 警告色**
 
**在庫良好 → 「在庫良好」という文字ラベル + 落ち着いた状態表示**
 
などを検討しています。
 
ただし「赤なら警告」だけに依存せず、**文字・配置・強調度も組み合わせる**方向です。
 
そして以前からの設計思想として、
 
**情報を管理するUIではなく、注意を管理するUI**
 
を目指しています。
 
100件の商品が正常なら100件すべてを強く見せるのではなく、**今対応すべき数件を優先的に見せる**わけです。
 
JavaScriptウェブアプリ構想.md
 
**認知負荷を下げるという方向性**
 
途中からかなり重要になってきた視点です。
 
「業務を覚えている人しか使えないシステム」ではなく、
 
**画面を見れば現在地と次の行動が分かる**
 
状態を目指しています。
 
そのため、
- 記憶への依存を減らす
- 正常情報に異常情報を埋もれさせない
- 判断を必要以上にユーザーへ要求しない
- 状態を明示する
- 次の操作を明示する
 
という考え方を重視しています。
 
これは障害者雇用だけを対象にするわけではありませんが、新人・パート職員・ITに不慣れな人・認知負荷を下げたい人にも使いやすい設計につながると考えています。
 
**印刷も重要な機能候補**
 
現在の設計メモでは、
 
**現在のWebアプリのUIをワンクリックで印刷できる**

これはかなり業務アプリらしい機能です。

という橋渡しができます。
