## 2. スコープ

▶ 書くこと：`sekkei.gensoku.md` の「入れる」「入れない」を転記。迷ったときに立ち戻る場所なので、「入れない」を省略しない。

### 2.1 v0.1に入れる機能
- 商品データ：商品名・現在庫・発注点・発注状態（未発注／発注済み）・入荷予定日を1品目1オブジェクトで持つ。初期データは「在庫に含めるもの」の12品目をJSに直書き
- 判定：在庫数・発注状態・入荷予定日から「入荷遅れ／入荷待ち／緊急発注／要発注／在庫良好」を導く（優先順位はNotion ENGT-385の表の通り）
- 表示：判定結果を文字ラベル＋色で表示し、要対応の品目を上に並べる
- 操作：「発注した」（入荷予定日入力）、「入荷した」（在庫数入力）、在庫数の変更
- 保存：操作のたびにlocalStorageへ保存し、ページを開き直しても状態が残る
- CSVエクスポート：現在の全品目をCSVとしてダウンロードする
- 印刷：ボタン1つでブラウザの印刷ダイアログを開く（印刷用の見た目調整は最小限）

### 2.2 v0.1に入れない機能（v0.2以降）
- 商品の追加・削除・発注点の変更（V0.1は12品目固定。変える場合はJSの初期データを書き換える）
- 発注数・入荷数の管理、発注履歴
- CSVインポート、複数端末での共有、ログイン
- 「発注を取り消す」操作（誤操作はlocalStorageをクリアして初期データに戻すことで対応）

### 2.3 技術的な前提
- プレーンなHTML / CSS / JavaScript のみ。フレームワーク・ビルドツール・npmは使わない
- 動作環境：（未記入：対象ブラウザ。例：PCのChrome最新版）
- データ保存：ブラウザのlocalStorage。サーバーなし
- 外部ファイルとの連携：CSVエクスポートのみ（インポートなし）

## 3. 利用フロー

▶ 書くこと：利用者が画面を開いてから閉じるまでの一連の操作を時系列で。`sekkei.gensoku.md` の「想定する利用フロー」を転記し、必要なら分岐を足す。

 利用者は備品・消耗品の管理担当者1人。業務の始まりや在庫を使った後にアプリを開く
- 画面を開くと、要対応の品目（緊急発注・要発注・要確認）が上に、対応不要の品目（入荷待ち・在庫良好）が下に表示される
- 要発注の品目を発注したら「発注した」ボタンを押し、入荷予定日を入れる → 入荷待ちになる
- 品物が届いたら「入荷した」ボタンを押し、入荷後の在庫数を入れる → 未発注に戻り、在庫数で再判定される
- 在庫を使ったら在庫数を更新する → 発注点を下回れば要発注になる
- 必要に応じて画面を印刷する、CSVをエクスポートする
